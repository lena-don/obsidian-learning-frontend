
### Введение
Цель — получить достаточно знаний и практики, чтобы устроиться на позицию Junior Frontend Developer. План скорректирован под реальные требования рынка: убраны темы, которые нужны Middle и Senior разработчикам, оставлен фокус на том, что спрашивают на собеседованиях и что нужно для выполнения реальных задач под руководством более опытных коллег.

## Этап 1. Инструменты разработчика (1–2 недели)

### 1. Командная строка (терминал)
**Что изучить:** `cd`, `ls`, `mkdir`, `rm`, `cp`, `mv`, `pwd`, запуск программ, флаги, Ctrl+C для остановки процесса.
**Зачем:** понадобится для запуска ==dev-сервера==, ==установки пакетов==, работы с Git.
**Уровень джуна:** уверенно перемещаться по папкам, создавать/удалять файлы, запускать скрипты из `package.json`.
**Избегать:** написания скриптов, прав доступа, глубокой настройки терминала.

### 2. Git и GitHub
**Что изучить:** `init`, `clone`, `add`, `commit`, `push`, `pull`, `branch`, `checkout`, `merge`, создание Pull Request на GitHub, решение конфликтов в простых случаях, `.gitignore`.
**Зачем:** даже на стажировке вы будете работать в команде через Git. Неумение пользоваться ветками — мгновенный провал на испытательном сроке.
**Уровень джуна:** уверенно вести свою ветку, делать PR, подтягивать изменения из main.
**Избегать:** rebase, squash, cherry-pick — узнаете позже, когда столкнётесь.

### 3. npm
**Что изучить:** `npm init`, `npm install`, `npm run`, что такое `package.json`, `node_modules`, `package-lock.json`, зачем нужны `dependencies` и `devDependencies`, как запустить чужой проект (clone → install → run).
**Зачем:** ни один современный проект не обходится без пакетного менеджера.
**Уровень джуна:** устанавливать зависимости, запускать скрипты, добавлять новые пакеты.
**Избегать:** публикации своих пакетов, разбора внутренней работы npm.

### 4. Vite (базово)
**Что изучить:** создание проекта через `npm create vite@latest`, структура проекта, запуск dev-сервера, сборка (`npm run build`), зачем нужна папка `dist`.
**Зачем:** Vite — самый простой способ начать современный фронтенд-проект. На работе вас посадят на уже настроенный проект, но вы должны понимать, что происходит при запуске.
**Уровень джуна:** создать проект, запустить, собрать, добавить простой плагин (например, для SVG).
**Избегать:** глубокой конфигурации Vite, написания своих плагинов, сравнения с Webpack.

## Этап 2. JavaScript — уверенный уровень (6–8 недель)

### 5. Основы языка — закрыть пробелы
**Что изучить:** типы данных (особенно `nll` vs `undefined`), операторы, сравнение (`==` vs `===`), шаблонные строки, условные конструкции, циклы (`for`, `for...of` — основной), тернарники, логические операторы (`&&`, `||`, `??`).
**Зачем:** это алфавит, без которого нельзя писать код.
**Уровень джуна:** писать читаемый код без подглядывания в шпаргалку.
**Избегать:** `switch` и `for` с индексом — на практике используют объекты-словари и `for...of`.

### 6. Функции
**Что изучить:** объявление функций, стрелочные функции, параметры и аргументы, rest-параметры, return, замыкания (что это такое и простой пример), колбэки.
**Зачем:** весь React построен на функциях. Замыкания нужны для понимания хуков.
**Уровень джуна:** писать функции, передавать их как аргументы, возвращать из функций.
**Избегать:** рекурсии, каррирования, частичного применения.

### 7. Массивы — главный инструмент фронтендера
**Что изучить:** `map`, `filter`, `find`, `some`, `every`, `includes`, `sort`, `slice`, `splice` (осторожно), spread-оператор для копирования, деструктуризация массивов.
**Зачем:** 70% кода фронтендера — это преобразование массивов данных для отображения в UI. `map` и `filter` — ваш хлеб.
**Уровень джуна:** без запинки написать `data.map(item => <Item key={item.id} />).filter(...)` и объяснить, что происходит.
**Избегать:** `reduce` на сложных примерах (достаточно понимать, что он делает, но на практике используют реже).

### 8. Объекты
**Что изучить:** создание, доступ к свойствам, деструктуризация, spread для копирования, `Object.keys`, `Object.values`, `Object.entries`, проверка наличия свойства, вложенные объекты.
**Зачем:** данные с сервера — это объекты. Работа с ними ежедневная.
**Уровень джуна:** уверенно доставать данные из вложенных объектов, не падать при `undefined`.
**Избегать:** прототипов, геттеров/сеттеров, дескрипторов.

### 9. Асинхронность — ключевая тема
**Что изучить:** проблема синхронного кода (блокировка), колбэки (кратко), Promise (`then`, `catch`, `finally`), `async/await`, `try/catch`, `Promise.all`, обработка ошибок.
**Зачем:** любые запросы к серверу — асинхронные. Без этого невозможно получить данные и отобразить их.
**Уровень джуна:** написать `const data = await fetch(url).then(res => res.json())` и обработать ошибку.
**Избегать:** генераторов, `Promise.race`, сложных цепочек промисов.

### 10. DOM и события (практический минимум)
**Что изучить:** что такое DOM, поиск элементов, `addEventListener`, делегирование событий (общее понимание), `event.target`, работа с `classList`, `dataset`.
**Зачем:** React сам работает с DOM, но вам нужно понимать, что происходит «под капотом», и уметь написать простой код без фреймворка.
**Уровень джуна:** написать обработчик клика, переключить класс, достать data-атрибут.
**Избегать:** ручного создания сложного DOM, шаблонизации — для этого есть React.

### 11. ES-модули
**Что изучить:** `import` / `export`, именованные и дефолтные экспорты, как импортировать функции из других файлов.
**Зачем:** любой проект разбит на модули. Вы будете писать `import { useState } from 'react'` в каждом файле.
**Уровень джуна:** уверенно экспортировать и импортировать функции, компоненты, константы.
**Избегать:** динамических импортов, CommonJS.

## Этап 3. Как работает веб (1–2 недели)

### 12. HTTP-протокол
**Что изучить:** запрос и ответ, методы (GET, POST, PUT, PATCH, DELETE), что такое заголовки, тело запроса, основные коды статусов (200, 201, 400, 401, 403, 404, 500).
**Зачем:** вы будете отправлять запросы и читать ответы. Понимание статусов помогает отладке.
**Уровень джуна:** понять по коду ошибки, в чём проблема (клиент или сервер), выбрать правильный метод для запроса.
**Избегать:** заголовков кэширования, CORS-заголовков на глубоком уровне.

### 13. Что такое API и REST
**Что изучить:** понятие API, REST-принципы (ресурсы, методы), формат JSON, как выглядит типичный ответ сервера, как читать документацию API.
**Зачем:** фронтенд работает с бэкендом через API. Нужно уметь отправлять запросы и понимать, что пришло в ответ.
**Уровень джуна:** взять любое публичное API (например, JSONPlaceholder) и получить/отправить данные.
**Избегать:** GraphQL, проектирования API.

### 14. DNS и URL — минимально необходимое
**Что изучить:** из чего состоит URL (протокол, домен, порт, путь, query-параметры), как браузер находит сервер по доменному имени (одна короткая фраза: «DNS переводит домен в IP-адрес»).
**Зачем:** вы будете работать с query-параметрами, разными окружениями (localhost, dev, prod), понимать, почему `http://localhost:3000` — это тоже URL.
**Уровень джуна:** распарсить URL на части, объяснить, зачем нужны query-параметры.
**Избегать:** типов DNS-записей, настройки DNS.

### 15. Браузер и DevTools
**Что изучить:** вкладка Network (фильтровать запросы, видеть статусы, тело ответов), Console, Elements, Application (localStorage, sessionStorage), как работают localStorage и sessionStorage, основы cookies.
**Зачем:** DevTools — главный инструмент отладки. Без него невозможно понять, почему запрос не работает.
**Уровень джуна:** увидеть упавший запрос в Network, посмотреть его статус и тело ответа, проверить localStorage.
**Избегать:** производительности рендеринга, Service Worker, Lighthouse.

### 16. Fetch API — практика
**Что изучить:** `fetch` — отправка запросов, `GET` с параметрами, `POST` с телом JSON, обработка ошибок, разбор ответа через `.json()`, `async/await` + `fetch`.
**Зачем:** основной способ взаимодействия фронтенда с сервером.
**Уровень джуна:** написать функцию `getUsers()`, `createUser(user)`, обработать ошибку сети и не-2xx статусы.
**Избегать:** axios на этом этапе — сначала поймите нативный `fetch`.

## Этап 4. React — уверенный Junior (8–10 недель)

### 17. Основы React — систематизировать
**Что изучить:** компоненты (функциональные), props, JSX, условный рендеринг, списки и keys, обработчики событий, состояние через `useState`, разница между props и state.
**Зачем:** это фундамент, без которого не построить приложение.
**Уровень джуна:** разбить макет на компоненты, передать данные через props, управлять состоянием.
**Избегать:** классовых компонентов (устарели), HOC, render props.

### 18. Хук useEffect
**Что изучить:** зачем нужен, синтаксис, массив зависимостей (пустой, с элементами, без массива), очистка эффекта (return), типичные сценарии: загрузка данных, подписка на события, синхронизация с внешним миром.
**Зачем:** без `useEffect` невозможно работать с сервером и внешними событиями.
**Уровень джуна:** загрузить данные с API при монтировании компонента, не создать бесконечный цикл.
**Избегать:** сложных эффектов с множеством зависимостей — обычно это сигнал для рефакторинга.

### 19. Работа с формами
**Что изучить:** управляемые поля (value + onChange), сбор данных из формы, валидация (ручная простая или через библиотеку React Hook Form), обработка submit, отображение ошибок.
**Зачем:** формы есть в каждом втором приложении: логин, регистрация, поиск, отзыв.
**Уровень джуна:** создать форму логина с валидацией и отправкой на сервер.
**Избегать:** Formik, сложных схем валидации.

### 20. Работа с API в React
**Что изучить:** паттерн «загрузка + ошибка + данные» (isLoading, isError, data), как показывать спиннер, как обрабатывать ошибки, простая загрузка через `useEffect` + `fetch`, кратко — TanStack Query (React Query) для решения проблемы кэширования.
**Зачем:** любое реальное приложение получает данные с сервера.
**Уровень джуна:** загрузить список с сервера, показать состояние загрузки, обработать ошибку, вывести данные.
**Избегать:** глубокой настройки React Query (оптимистичные обновления, инвалидация — узнаете на практике).

### 21. React Router
**Что изучить:** установка, `BrowserRouter`, `Routes`, `Route`, `Link`, `useNavigate`, `useParams`, вложенные маршруты (базово).
**Зачем:** многостраничные приложения.
**Уровень джуна:** создать 3–4 маршрута, переходить между страницами, получать параметр из URL.
**Избегать:** защищённых маршрутов (придёт позже с реальным проектом).

### 22. Управление состоянием: Context API
**Что изучить:** зачем нужно глобальное состояние, создание контекста, `useContext`, Provider, типичный пример (тема, пользователь).
**Зачем:** не всё состояние можно держать в одном компоненте.
**Уровень джуна:** вынести пользователя или тему в контекст, получить доступ из любого компонента.
**Избегать:** Redux, Zustand на данном этапе — Context API достаточно.

### 23. Стилизация в React
**Что изучить:** подходы: обычный CSS, CSS Modules, Tailwind CSS (основы). Выберите один основной (рекомендую Tailwind — стандарт в индустрии) и практикуйте.
**Зачем:** вы дизайнер, вам важно создавать красивые интерфейсы.
**Уровень джуна:** сверстать интерфейс в React, используя выбранный подход.
**Избегать:** CSS-in-JS (styled-components), сравнения всех подходов.

## Этап 5. TypeScript — практический минимум (2–3 недели)

### 24. TypeScript для React-разработчика
**Что изучить:** базовые типы (`string`, `number`, `boolean`, `array`, `object`), интерфейсы для описания объектов, union-типы, опциональные свойства, generics (только чтобы читать код библиотек), типизация props, state, событий.
**Зачем:** большинство вакансий требует TypeScript. Он помогает избегать ошибок и улучшает подсказки в редакторе.
**Уровень джуна:** типизировать props компонента, состояние, функции, работать с данными от API (описать интерфейс ответа).
**Избегать:** сложных типов (`keyof`, `infer`, условные типы), декораторов.

## Этап 6. Тестирование — базово (1–2 недели)

### 25. Основы тестирования
**Что изучить:** зачем нужны тесты, как написать простой тест на Vitest (или Jest), как протестировать функцию, React Testing Library — отрендерить компонент, найти элемент, кликнуть, проверить результат.
**Зачем:** тесты — часть рабочего процесса. На собеседовании вас могут спросить, писали ли вы тесты.
**Уровень джуна:** написать тест на простое вычисление и тест на рендер компонента.
**Избегать:** E2E-тестов (Playwright, Cypress), снэпшот-тестов.

## Этап 7. Практика и портфолио (4–6 недель)

### 26. Проект 1: Приложение на React + публичное API
**Что сделать:** приложение с несколькими страницами (React Router), загрузкой данных (fetch), формами, Tailwind. Примеры: каталог фильмов, погода, список задач с сохранением в localStorage.
**Зачем:** первый самостоятельный проект, демонстрация всех навыков.
**Критерий готовности:** проект задеплоен (Vercel/Netlify), код в GitHub, README с описанием.

### 27. Проект 2: Клон известного сервиса (упрощённый)
**Что сделать:** например, упрощённый Trello, Instagram, Twitter. Фокус: сложность состояния, взаимодействия между компонентами, работа с формами, CRUD-операции (создание, чтение, обновление, удаление).
**Зачем:** второй проект показывает глубину понимания, его можно обсуждать на собеседовании.
**Критерий готовности:** все основные функции работают, есть валидация, обработка ошибок, проект задеплоен.

### 28. Резюме и подготовка к собеседованию
**Что сделать:** актуализировать резюме (проекты, стек, ссылки на GitHub), подготовить ответы на типичные вопросы по JS и React, повторить ключевые темы: замыкания, `useEffect`, разница `==` и `===`, что такое ключи в списках, как работает `fetch`.
**Зачем:** конечная цель — трудоустройство.
**Критерий готовности:** вы можете уверенно рассказать о своих проектах, объяснить технические решения, ответить на вопросы уровня junior.

## Чего нет в плане и почему
- **Redux / Zustand / MobX** — на junior-позиции обычно не требуется. Context API достаточно для старта.
- **Next.js / SSR** — отдельная технология, которую изучают после уверенного React.
- **Node.js / Express** — не обязательно для junior фронтендера, появится позже.
- **Docker / CI/CD** — на junior-позиции настройкой не занимаетесь, но полезно знать общие принципы (не тратьте время сейчас).
- **Алгоритмы и структуры данных** — на собеседованиях джунов спрашивают базово (массив, объект, цикл), leetcode не нужен на этом этапе.

## Реалистичный график
При занятиях 10–15 часов в неделю весь план займёт **5–6 месяцев**. Если вы можете уделять 25+ часов — уложитесь в 3–4 месяца.

**Совет:** не застревайте на теории. Ставьте мини-цели (сделать форму, загрузить список, настроить роутинг) и закрепляйте каждую тему небольшим кодом. Портфолио из двух хороших проектов на собеседовании ценнее, чем знание всех тем без практики.
