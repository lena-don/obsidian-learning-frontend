**HTTP** (Hypertext Transfer Protocol протокол передачи гипертекста) — это набор правил (протокол) для передачи данных между клиентом (например, браузером) и сервером, на котором находится сайт. Обычный HTTP не шифрует данные. Для защиты конфиденциальной информации используют защищенную версию **HTTPS** (Hyper Text Transfer Protocol Secure)

**Протоколы передачи данных** (набло соглашений, которые определяют обмен данными между различными программами) бывают:
- физическими — как и какие сигналы идут от одного устройства к другому
- логическими — отвечают за смысл и передачу данных, когда физическая связь уже установлена 

## Как это работает

- **Клиент-сервер**: Клиент (например, браузер) отправляет запрос, а сервер принимает его и возвращает ответ.
- **Запрос и ответ**: Запрос содержит метод и адрес нужного ресурса, а ответ — статус и сами данные (текст, картинку, видео).
- **Без сохранения состояния**: Протокол не имеет памяти, каждый новый запрос обрабатывается отдельно от предыдущих.
#### Основные нюансы
- **Методы**: Самые популярные действия — `GET` (получить данные) и `POST` (отправить данные).
- **Безопасность**: Обычный HTTP передает данные в открытом виде. Для защиты личной информации и паролей используют безопасную версию с шифрованием — HTTPS.


## HTTP-запрос
HTTP-запрос — это сообщение, которое клиент (например, браузер) отправляет на сервер, чтобы получить данные, отправить форму или выполнить другое действие
#### Из чего состоит HTTP-запрос
- **Стартовая строка:** метод (действие), путь к ресурсу (URI) и версия протокола.
- **Заголовки (Headers):** параметры, которые передают служебную информацию (тип контента, куки, данные о браузере).
- **Тело запроса (Body):** данные, которые отправляются на сервер (например, текст из формы или JSON), используется не всегда.

## Методы HTTP

Метод HTTP — это команда, которая указывает серверу, какое действие нужно выполнить с конкретным ресурсом

[Методы HTTP запроса от MDN Web Docs](https://developer.mozilla.org/ru/docs/Web/HTTP/Reference/Methods) 

#### Основные методы HTTP

- **GET** — запрашивает данные с сервера без изменения их состояния. **Пример:** `GET /users` возвращает список всех пользователей.

- **POST** — отправляет новые данные на сервер для создания ресурса. **Пример:** `POST /users` с телом запроса `{ "name": "Иван" }` создаст нового пользователя.

- **PUT** — заменяет существующий ресурс целиком или создает его, если его нет по указанному адресу. **Пример:** `PUT /users/5` полностью обновит данные пользователя с идентификатором 5.

- **PATCH** — вносит частичные изменения в существующий ресурс. **Пример:** `PATCH /users/5` с телом `{ "email": "new@mail.ru" }` изменит только почту пользователя.

- **DELETE** — удаляет указанный ресурс. **Пример:** `DELETE /users/5` удалит пользователя под номером 5.

- * **OPTION** — используется для определения параметров соединения, доступных методов и требований для конкретного ресурса или сервера целиком.




## HTTP response status codes

Коды ответов HTTP — это трёхзначные числа, которыми сервер сообщает клиенту (например, браузеру) результат обработки его запроса.

Они делятся на пять основных классов по первой цифре: 
#### Классы кодов HTTP
- **1xx (Информационные)**: запрос получен, сервер продолжает обработку.
- **2xx (Успешно)**: запрос успешно получен, понят и обработан.
- **3xx (Перенаправление)**: для завершения запроса нужно сделать дополнительные действия (редирект).
- **4xx (Ошибка клиента)**: в запросе есть ошибка или неверный синтаксис.
- **5xx (Ошибка сервера)**: сервер не смог выполнить корректный на вид запрос.

[Полный список на MDN Web Docs](https://developer.mozilla.org/ru/docs/Web/HTTP/Reference/Status).

#### Популярные коды ответов:
- **200 OK**: запрос выполнен успешно, данные переданы.
- **201 Created**: запрос клиента был успешно выполнен, и в результате на сервере появилось что-то новое (чаще всего отправляется в ответ на методы POST при создании объекта или PUT)
- **301 Moved Permanently**: ресурс навсегда перемещен на новый адрес.
- **304 Not Modified**: контент не изменился, используется кэш браузера.
- **400 Bad Request**: сервер не понял запрос из-за синтаксической ошибки.
- **401 Unauthorized**: нет авторизации, нужны учетные данные.
- **403 Forbidden**: доступ запрещен, сервер понял запрос, но отказывается его выполнять.
- **404 Not Found**: запрашиваемый ресурс не найден.
- **500 Internal Server Error**: внутренняя ошибка и сбой на сервере.
- **502 Bad Gateway**: один сервер получил неверный ответ от другого шлюза.
- **503 Service Unavailable**: сервис временно недоступен из-за перегрузки или техработ
