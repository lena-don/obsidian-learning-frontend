## Node.JS

**Node.js** — [[Среда выполнения||среда выполнения]] JavaScript, которая позволяет запускать код вне браузера (например, прямо на компьютере или на сервере)

#### Немного истории
Изначально язык JavaScript жил только в браузерах (Chrome, Safari, Firefox) и отвечал за красивые анимации, кнопочки и всплывающие окна на сайтах. Но в 2009 году программисты взяли движок V8 из браузера Google Chrome (он очень быстро переводит код в понятный компьютеру язык) и «вытащили» его наружу. 

Так появился **Node.js**. Он дал JavaScript новые суперсилы: теперь с его помощью можно читать и создавать файлы на жестком диске, управлять базами данных и принимать сетевые запросы от пользователей.

#### Зачем нужен Node.js
- **Создание серверов (бэкенд):** Раньше для создания сайтов на сервере нужно было учить другие языки (PHP, Python, Java). Теперь сайт целиком — и то, что видит пользователь, и внутреннюю логику — можно написать на одном и том же JavaScript. 
- **Приложения в реальном времени:** Чаты, онлайн-игры, мессенджеры и совместные документы работают быстро и без задержек, потому что Node.js умеет обрабатывать тысячи одновременных запросов, не «зависая» при ожидании ответа. 
- **Инструменты для разработки:** На Node.js работают многие современные помощники программистов (например, сборщики кода и пакетные менеджеры вроде npm), помогающие создавать сайты и приложения.

# Node Package Manager

**npm** — стандартный [[Менеджер пакетов|менеджер пакетов]] и огромный онлайн-репозиторий для языка программирования JavaScript. Автоматически устанавливается вместе с платформой Node.js.

### Основные команды `npm`
- **`npm init`**  
    Создает новый проект и файл конфигурации `package.json`, в котором хранится «паспорт» приложения (название, версия, зависимости). Флаг `-y` (или `--yes`) позволяет пропустить вопросы и создать файл с настройками по умолчанию. 

- **`npm install`** (или сокращенно **`npm i`**)  
    Скачивает и устанавливает все нужные библиотеки и зависимости, указанные в файле `package.json`, в папку `node_modules`. Если передать имя пакета (например, `npm install express`), он добавится в проект автоматически.

- **`npm run <имя_скрипта>`**  
    Запускает пользовательские команды (скрипты), которые заранее прописаны в блоке `"scripts"` файла `package.json` (например, `npm run build` для сборки проекта или `npm run start` для запуска сервера). Вызов команды `npm run` без параметров покажет список всех доступных скриптов.


### `package.json` (Паспорт проекта)
Это главный конфигурационный файл проекта. Он создается вручную или через команду `npm init`. 
- **Что делает:** Хранит общую информацию о проекте (название, версию, автора, лицензию).
- **Главное содержимое:** Список всех внешних библиотек (зависимостей), нужных для работы приложения (`dependencies`) и разработки (`devDependencies`), а также удобные команды-скрипты для запуска проекта (`scripts`, например, `npm run start`).
- **Размер:** Очень маленький текстовый файл. Мы пишем его сами или редактируем. 

В npm поле `dependencies` в файле `package.json` содержит список сторонних пакетов и их версий, необходимых для работы приложения **в продакшене**. 

#### Главные виды зависимостей в npm:

- **`dependencies` (Основные):** Пакеты, без которых приложение не сможет работать после сборки и запуска на сервере или у пользователя (например, `express`, `react`, `lodash`). Устанавливаются командами вроде `npm install <package>`. 

- **`devDependencies` (Для разработки):** Инструменты и библиотеки, которые нужны только в процессе написания кода, тестирования или сборки (например, `jest`, `eslint`, `webpack`). Они помечаются флагом `-D` или `--save-dev` и не попадают в итоговый рабочий продукт. 

- **`peerDependencies` (Совместимость):** Указывают, что ваш пакет ожидает наличия определенной библиотеки в проекте, куда он устанавливается (часто используется при создании плагинов или UI-библиотек).


### `node_modules` (Склад библиотек)
Это папка, в которой хранятся сами физические файлы всех установленных библиотек и их внутренних зависимостей (подзависимостей).
- **Что делает:** Позволяет вашему коду использовать сторонний функционал (например, подключать React, Express или Lodash через `require()` или `import`).
- **Особенности:** Эта папка весит очень много, так как содержит тысячи файлов. Ее **никогда не добавляют** в систему контроля версий (Git), потому что её можно в любой момент воссоздать заново командой `npm install`.


### `package-lock.json` (Точная карта сборки)
Это файл блокировки, который автоматически создается и обновляется пакетным менеджером `npm` при установке пакетов.
- **Что делает:** Фиксирует **точные версии** всех установленных библиотек и подзависимостей, которые скачались в папку `node_modules` на вашем компьютере.
- **Зачем нужен:** В `package.json` версия библиотеки может быть указана с символом `^` (например, `^1.2.3`, то есть «ставим версию 1.2.3 или выше»). Без лока-файла у вас и вашего коллеги на другом компьютере через неделю могут установиться немного разные минорные версии пакетов, что приведет к багам. `package-lock.json` гарантирует, что у всех на всех компьютерах будет абсолютно идентичное дерево зависимостей.
- **Размер:** Большой текстовый файл (его нужно сохранять в Git)



### Как запустить чужой проект с nmp

- **Установите Node.js**  
    Убедитесь, что у вас установлен Node.js (вместе с ним автоматически установится и npm). Проверить это можно в терминале с помощью команд `node -v` и `npm -v`.

- **Откройте папку проекта**  
    Перейдите в терминале (командной строке) в корневую папку скачанного или клонированного проекта (через `git clone {ссылка на проект}`):
```
cd путь/к/папке/проекта
```

- **Установите зависимости**  
    Запустите скачивание всех необходимых библиотек, указанных в проекте:
 
```
npm install
```

_Эта команда создаст папку `node_modules`, куда загружаются все компоненты, нужные для работы кода._ 

- **Найдите команду для запуска**  
    Откройте файл `package.json` в корне проекта и найдите блок `"scripts"`. Там будут прописаны команды для запуска. Чаще всего используются:
    - `npm run dev` (для режима разработки с автоматическим обновлением).
    - `npm run start` (для обычного или продакшн-запуска).
    - `npm run build` (если проект нужно сначала собрать, а потом запустить).

- **Запустите проект**  
    Введите нужную команду в терминале, например:
```
npm run start
```



### **npm, Yarn и pnpm** 
это три главных менеджера пакетов для экосистемы Node.js.

|Критерий|**npm**|**Yarn (Classic / Modern v4+)**|**pnpm**|
|---|---|---|---|
|**Установка**|Идет в комплекте с Node.js|Через Corepack или глобально (`npm i -g yarn`)|Через Corepack, скрипт или `npm i -g pnpm`|
|**Скорость**|Средняя (последовательная / частично параллельная)|Высокая (параллельная загрузка пакетов)|**Самая высокая** (за счет конвейерной установки)|
|**Дисковое пространство**|Дублирует пакеты в каждом проекте (тяжелая `node_modules`)|Дублирует пакеты (в v1) или использует Plug'n'Play (v4)|**Экономит место** (одно глобальное хранилище на ПК)|
|**Структура `node_modules`**|Плоская (Flat)|Плоская (Flat) или виртуальная (PnP)|**Вложенная (жёсткие ссылки)**|
|**Файл блокировки**|`package-lock.json`|`yarn.lock`|`pnpm-lock.yaml`|
|**Монорепозитории (Workspaces)**|Базовая поддержка|**Отличная поддержка** (включая плагины)|Отличная поддержка (очень популярна)|
|**Безопасность**|Стандартная (сканирование через `npm audit`)|Высокая (проверка контрольных сумм)|**Максимальная** (исключает «фантомные» зависимости)|

#### Архитектурные особенности: В чем разница?

##### 1. Структура папки `node_modules`
- **npm и Yarn (Classic):** Создают плоскую структуру. Если пакет `A` зависит от пакета `B`, то `B` будет лежать на самом верхнем уровне `node_modules`. Это позволяет коду обращаться к пакетам, которые вы напрямую не устанавливали (так называемые **фантомные зависимости**).
- **pnpm:** Использует систему жестких ссылок (hard links). Пакеты скачиваются в одно общее глобальное хранилище на вашем диске, а в проекте создаются ссылки на них. Ваша программа физически видит только те пакеты, которые вы жестко прописали в `package.json`. Это предотвращает баги с фантомными зависимостями и экономит гигабайты памяти на диске.
##### 2. Безопасность и Strict Modern
- За счет вложенной структуры ссылок **pnpm** считается самым строгим менеджером. Если разработчик забыл указать зависимость в `package.json`, код просто не запустится, что страхует от поломок в production. Современный **Yarn (v4)** предлагает похожую изоляцию с помощью режима Plug'n'Play (PnP), который полностью избавляется от папки `node_modules`, генерируя вместо неё карту зависимостей в `.pnp.cjs`.
