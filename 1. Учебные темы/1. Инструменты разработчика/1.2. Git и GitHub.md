**Git** — это распределенная система контроля версий
- Она устанавливается на мой компьютер.
- Позволяет сохранять историю всех изменений в файлах.
- Помогает вернуться к любой старой версии кода, если новая не работает.
- Работает локально и без интернета. 

**GitHub** — это веб-платформа и хостинг для проектов, которые используют Git. 
- Это сайт в интернете, где можно хранить свой код в облаке.
- Помогает разработчикам работать над общими проектами в команде.
- Предоставляет удобный графический интерфейс для просмотра кода, обсуждения ошибок и предложений по улучшению.

#### Основные команды
- **`git init`** — создает новый локальный репозиторий в текущей папке.
- **`git clone <URL>`** — скачивает существующий удаленный репозиторий вместе с его историей на ваш компьютер.
- **`git add <файл>`** — добавляет измененные файлы в индекс (staging area) для подготовки к сохранению.
- **`git commit -m "сообщение"`** — сохраняет подготовленные файлы из индекса в историю репозитория в виде коммита.
- **`git push`** — отправляет ваши локальные коммиты в удаленный репозиторий.
- **`git pull`** — скачивает свежие изменения из удаленного репозитория и сразу объединяет их с текущей веткой.
- **`git branch`** — показывает список веток или создает новую ветку.
- **`git checkout <ветка>`** — переключает на другую ветку или восстанавливает файлы
- **`git switch <ветка>`**  — для переключения между ветками в репозитории
	-   **`git switch -c <название-новой-ветки>`** — cоздание новой ветки и переход на неё  (аналог  `git checkout -b`).
	- **`git switch -`**  — возврат на предыдущую ветку (аналогично команде `cd -` в терминале).
	- **`git switch --detach <коммит>`**  — отсоединение HEAD (detached HEAD), позволяет переключиться на конкретный коммит для его осмотра или экспериментов
- **`git merge <ветка>`** — объединяет изменения из указанной ветки в вашу текущую активную ветку. 
- **`git diff --staged`** — показывает разницу между проиндексированными изменениями (staging area) и последним коммитом.
- **`git stash`** временно сохраняет (прячет) незавершенные изменения в рабочей директории, чтобы вы могли переключиться на другую ветку или выполнить другие задачи без создания коммита.


#### Staging area
Staging area (или индекс) в Git — это промежуточная область памяти, где хранятся подготовленные изменения перед их сохранением в истории проекта

Как это работает
- **Рабочая папка (Working Directory):** место, где вы меняете файлы в данный момент.
- **Staging Area (Index):** черновик или список будущих изменений. Команда `git add` переносит файлы из рабочей папки сюда.
- **Репозиторий (Repository):** постоянная история проекта. Команда `git commit` сохраняет файлы из staging area в репозиторий.
- 
Зачем нужна staging area
- **Выбор изменений:** можно отправить в коммит только часть файлов или даже отдельные строчки кода, а остальное оставить на потом.
- **Проверка кода:** перед сохранением можно перепроверить свои правки через `git status` и `git diff --staged`.
- **Чистая история:** помогает разделять большие задачи на аккуратные и понятные логические коммиты.


### Связать локальный и удалённые репозитории
Например, у нас есть проект, над которым мы работаем локально на своём компьютере, и мы хотим опубликовать его в гитхабе, чтобы иметь к проекту доступ с других устройств, или показать проект другим людям, или что-то ещё такое. Порядок действий

##### 0. Предварительно:
1. **Установлен Git** локально (`git --version`).
2. **Настроены [user.name](https://user.name/) и user.email**:
	```
	git config --global user.name "Ваше Имя"
    git config --global user.email "you@example.com"
    ```
3. **Есть аккаунт на GitHub** и настроена аутентификация (SSH-ключ или Personal Access Token).

#### Шаг 1. Создать пустой репозиторий на GitHub
На [github.com](https://github.com/) → **New repository**:
- **НЕ** ставьте галочки "Add README", "Add .gitignore", "Choose a license" — иначе получите расхождение историй и придётся делать `pull --rebase`.
После создания GitHub покажет URL — например:
- HTTPS: `https://github.com/username/repo.git`
- SSH: `git@github.com:username/repo.git`

#### Шаг 2. Инициализировать Git в локальном проекте
Перейдите в папку проекта:
```
cd /path/to/project
git init
```
Проверьте, что Git не пытается закоммитить мусор. Создайте `.gitignore` (например, для Node.js, Python и т.п.).

#### Шаг 3. Сделать первый коммит
```
git add .
git commit -m "Initial commit"
```
Убедитесь, что ветка называется `main` (современный стандарт):
```
git branch -M main
```

#### Шаг 4. Привязать удалённый репозиторий
```
git remote add origin git@github.com:username/repo.git
```
Проверить:
```
git remote -v
```

#### Шаг 5. Отправить код на GitHub
```
git push -u origin main
```
Флаг `-u` (он же `--set-upstream`) запоминает связку «локальная ветка `main` ↔ удалённая `origin/main`». После этого достаточно просто `git push` и `git pull`.

#### Готово. Дальнейший рабочий цикл
```
git add .
git commit -m "Что сделано"
git push              # отправить на GitHub
git pull              # забрать изменения с GitHub
```
Чтобы работать с другого устройства — там достаточно:
```
git clone git@github.com:username/repo.git
```

#### Если репозиторий уже клонирован, но вы хотите сменить remote
```
git remote set-url origin git@github.com:username/new-repo.git
```
