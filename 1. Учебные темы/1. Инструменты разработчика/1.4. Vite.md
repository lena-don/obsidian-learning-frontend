## Более подробный разбор того, как работает Vite
#### Основные компоненты Vite
- **Сервер разработки**: Запускается мгновенно за счет использования нативных [[ES-модули||ES-модулей]] в браузере без предварительной сборки всего кода.
- **[[HMR горячая замена модулей]]**: Изменения в коде отображаются на странице за миллисекунды, независимо от размера проекта.
- **Команда сборки (Production build)**: Объединяет и оптимизирует файлы для публикации на сервер с помощью инструментов вроде Rollup или Rolldown.

#### Зачем его используют
- **Скорость**: Работает значительно быстрее классических сборщиков вроде Webpack на больших проектах.
- **Универсальность**: Поддерживает популярные фронтенд-фреймворки (Vue.js, React, Svelte, Solid и др.) и TypeScript «из коробки».
- **Удобство**: Имеет простую настройку и расширяется с помощью плагинов.

### Папка `dist` в Vite —
==это директория, куда инструмент сохраняет готовую оптимизированную [продакшен-сборку вашего приложения](https://vite-docs.ru/guide/build) после выполнения команды== `npm run build`. 

_или,_ Папка **dist** в сборщике **Vite** — это ==каталог с готовыми к публикации файлами сайта или приложения, полученными после выполнения команды сборки== (`vite build`).

#### Что означает dist
- **Расшифровка:** Сокращение от англ. **distribution** (дистрибутив, распространение).
- **Суть:** Это итоговая папка, куда Vite складывает скомпилированный, минифицированный и оптимизированный код (HTML, JavaScript, CSS, изображения), готовый для загрузки на веб-сервер или хостинг. 

#### Главные особенности папки dist
- **Автоматическая генерация:** Создается сборщиком с нуля при каждой новой сборке проекта.
- **Имя по умолчанию:** Называется `dist`, но его можно изменить в настройках конфигурации (`vite.config.js`) через параметр `build.outDir` (см ниже) 
- **Только для продакшена (Production):** Файлы из этой папки не нужны для разработки, их передают на хостинг (например, Vercel, Netlify, GitHub Pages или ваш собственный сервер). 
- **Нельзя редактировать вручную:** Все изменения в папки `dist` будут стерты при следующей сборке проекта — править код нужно в исходной папке (например, `src`).

### Что находится внутри `dist`
- **`index.html`** — главный минимизированный HTML-файл.
- **Скомпилированные файлы** — минифицированные и оптимизированные JS- и CSS-файлы (обычно в папке `dist/assets`), готовые для загрузки на веб-сервер или хостинг. 

#### Как создать и проверить папку `dist`
- Запустите сборку проекта в терминале:
```
npm run build
```

- Проверьте результат локально перед деплоем с помощью команды:
```
npm run preview
```

#### Как изменить имя папки `dist`
Если вам нужно изменить название выходной папки (например, на `build`), откройте файл конфигурации `vite.config.js` (или `vite.config.ts`) и добавьте параметр `outDir` в секцию `build`:
```
export default {
  build: {
   outDir: 'build', // меняет dist на build
  },
}
```




## Более сжатый разбор того, как работает Vite
Vite — это ==современный [инструмент сборки фронтенда](https://laravel.su/docs/13.x/vite), который работает значительно быстрее классических сборщиков вроде Webpack==. 

Его работа опирается на две главные составляющие: **esbuild** (для быстрой трансформации кода) и **Rollup** (для финальной сборки на продакшен).

### Как устроен режим разработки (Dev Server)
В отличие от Webpack, который собирает весь проект в единый бандл перед запуском, Vite использует подход без предварительной сборки бандлов.
- **Нативные ES-модули (ESM):** Сервер разработки передает исходный код браузеру напрямую. Браузер сам запрашивает нужные модули через стандартные `import`-директивы по мере необходимости.
- **Трансформация «на лету»:** Код компилируется и отдается браузеру только в тот момент, когда запрашивается конкретная страница.
- **Использование esbuild:** Для конвертации JSX, TypeScript или Vue-компонентов Vite использует esbuild, написанный на Go. Он выполняет трансформацию в 10–100 раз быстрее традиционных JS-сборщиков.

### Предварительное объединение зависимостей (Dependency Pre-Bundling)
Чтобы браузер не захлебывался от тысяч мелких запросов к файлам из папки `node_modules` (например, у React или Lodash), Vite делает две вещи:
- **Кэширование Vendor-модулей:** Тяжелые сторонние библиотеки (статические зависимости) предварительно объединяются в крупные ES-модули с помощью того же `esbuild` при первом запуске.
- **Оптимизация сети:** Это сокращает количество сетевых запросов в браузере и ускоряет загрузку.

### Горячая перезагрузка (HMR)
- **Точечное обновление:** Когда вы меняете файл, Vite пересобирает только конкретный модуль, связь которого с текущим компонентом нарушилась. 
- **Мгновенный отклик:** Замена модуля происходит за миллисекунды независимо от общего размера проекта, так как не нужно пересчитывать весь граф зависимостей.

### Как устроена сборка для продакшена (Production Build)
Хотя для разработки Vite не использует бандлер, для продакшена он применяет Rollup.
- **Оптимизация:** Родная сборка через Rollup включает минификацию, разделение кода (_code-splitting_), «тряску деревьев» (_tree-shaking_) и правильную подготовку ассетов для статического хостинга.
- **Плагины:** Архитектура Vite позволяет легко подключать плагины (совместимые с экосистемой Rollup) для расширения функционала.
