**Инжектить** (от англ. _to inject_ — впрыскивать, внедрять) в IT и программировании означает ==программно внедрять один компонент, код, данные или зависимость внутрь другого==. 

### Основные значения в IT

- **Внедрение зависимостей (Dependency Injection / DI):** Передача готового объекта или сервиса (зависимости) в другой класс или функцию вместо создания этого объекта внутри них. Популярно в фреймворках вроде Angular, Spring или Laravel. Пример: _«инжектить сервис авторизации в компонент»_.

- **Внедрение кода (Injection / Инъекция):** Запуск или вставка стороннего кода в чужой процесс, память или веб-страницу.
    - _DLL-инъекция_ — внедрение динамической библиотеки в память запущенной программы.
    - _SQL-инъекция_ — уязвимость, при которой в базу данных внедряется вредоносный SQL-код. 

- **Введение данных в тесты:** Передача мок-данных (mock data) или заглушек в тестируемый модуль.




Противоположное:
# Eject
 **Eject** (от англ. _извлечь / выбросить_) — ==**выход из-под управления какого-либо фреймворка или инструмента автоматизации** ради получения полного доступа к низкоуровневым конфигурационным файлам==.

Проще говоря, это процесс «вскрытия капота» проекта, когда вы отказываетесь от упрощенной работы ради максимальной свободы действий.
##### Самый известный пример: Create React App (`npm run eject`)
В экосистеме **React** этот термин стал нарицательным благодаря утилите Create React App (CRA).
- **До eject:** Все сложные инструменты сборщика (Webpack, Babel, PostCSS) скрыты внутри одной зависимости (`react-scripts`). Разработчик видит чистый проект и не думает о настройках сборки.
- **После выполнения `npm run eject`:** Скрытая конфигурация «выворачивается наружу». В корне проекта появляются файлы `webpack.config.js`, `paths.js` и десятки других настроек. Команда `react-scripts` удаляется.
